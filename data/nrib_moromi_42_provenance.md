**ADR-018 の負債一覧の記述「出典はファイル名のみ」は不正確。** 実際には `data/README.md` に発行元・DB名・URL・取得日・仕込条件まで書かれている。負債の実体は「**sources.csv（出典台帳）に未登録**」であり、ADR-018 決定事項2「台帳に載っていない資料は取り込まない」に抵触している点である。

### 想定の答え合わせ
- 全国新酒鑑評会 出品酒の分析値 → **違う**。鑑評会出品酒は大吟醸で総米も桁違い。本データは総米20kg・60%精米・純米。
- 清酒製造技術（赤本）のもろみ経過例 → **違う**。赤本 p.266 の醪経過表は普通酒醪・吟醸酒醪の各1例で、42件の表は存在しない。
- 正解は **酒類総合研究所の「酒類醸造講習（清酒コース）」で受講生が実施した小仕込み42本の実測 DB**。

### 結論
**元資料はローカルにもDriveにも存在しない。** 実体は NRIB の公開Webデータベース（`nribjyo.nrib.go.jp/moromi/jitumoromis`）であり、42件の要約値だけが手作業でこのJSONに転記された状態。ADR-018 の「Driveパスを記す」要件を満たすには **DBのスナップショット（CSV/HTML/PDF）をDriveに保存する作業が先** に必要。

### オーナー確認が要る点（これが決まれば台帳行が確定する）
1. **DBの公開年・データ年度（どの醸造年度の講習分か）** — 42件が単年か複数年の合算か。
2. **原本スナップショットを取るか** — Web DB は改訂・閉鎖で消える。Drive `読み物/日本酒資料/` 配下に CSV か印刷PDF を保存すれば `drive_path` が埋まり、T1 として正式登録できる。
3. **type / extract_mode の扱い** — 現行の `extract_books.py` は `type=教科書/試験問題` の行しか処理しない。Webデータベースは新カテゴリなので、(a) 台帳には載せるが sake-kb には取り込まない「引用専用行」にするか、(b) 数表用の取り込み経路を足すか。**足さない案＝(a)** を推す（42件の数値はこのJSONが持っており、KBで全文検索する価値が薄い）。
4. **`data/README.md` と JSON の不一致をどう埋めるか** — 下記 §4 参照。

### 読み取り

- **明らかな異常仕込みは4件**（no.5・6＝最高品温24.1℃/13日の高温速攻、no.9＝maxB11・アル8.5%・日本酒度−33.5の発酵停滞、no.37＝アル12.9%・アミノ酸度0.64の低アル）。これは `MOROMI_MODEL_SPEC.md` §8.10 が「正常クラスタ38仕込」として除外した4件と**一致**（除外後の日本酒度 −17.4〜+9.4・中央0.0 が spec の「−17〜+9/中央0」と完全一致）。データの内部整合は取れている。
- **残る38件はすべて教科書の実務的な幅に収まる**。maxT 12.4〜16.4（15℃前後）、days 15〜21（20〜22日型）、maxB 5.9〜9.6（標準7〜8を中心）で、講習の小仕込みらしく低温・やや短期に寄っている。
- **教科書レンジから系統的にずれるのは酸度1点のみ**：42件中24件が赤本 p.266 の醪末期レンジ（2.0〜2.8）を**下回る**（1.4〜1.9）。赤本の数値はきょうかい6/7/9/10号を前提にしており、README が挙げる使用酵母（協会601〜1801号）の低酸性・小仕込み・純米という条件差で説明がつく可能性が高いが、**現時点で台帳資料からの裏は取れていない**。ADR-018 の作法どおり、この差を「モデル検証の根拠」に使うなら要検証扱いにすべき。
- alc が18%超に多く出るのも同方向のずれ（総米20kg の小仕込みは温度・物質交換が速く、教科書の30日標準より高アルに振れる）。spec §8.10 も同じ解釈を書いており、実測と説明が矛盾しない。

## 4. 付随して見つかった不整合（要判断）

`data/README.md` と `MOROMI_MODEL_SPEC.md` §8.10 は「**全42件の香気成分・酵母・残糖も取得（`data/`に全項目）**」と書き、収録項目として `kasu`（糟歩合）`gluc`（グルコース残糖）`yeast`（酵母種類）`kapro`（カプロン酸エチル）`isoac`（酢酸イソアミル）`etac`・`isoal` を挙げている。

しかし **`nrib_moromi_42.json` に実在するキーは `no, maxT, maxB, days, alc, nihon, sando, amino` の8つだけ**（全3,784バイト）。

つまり §8.10 の主要な検証結果——
- 残糖(グルコース)×日本酒度 **r=−0.80**
- 吟醸系酵母のカプロン酸エチル平均 4.60 vs 普通系 1.85
- 糟歩合×アルコール **r=−0.38**

——は、**リポジトリに残っているデータからは再現できない**。これらの列は取得セッション内にだけ存在し、保存されなかったとみられる。出典を台帳登録しても、この3つの相関は「出典はあるが検証データが手元に無い」状態のままになる。オーナー判断が要る：(a) NRIB DB から全項目を再取得してJSONに追記する、(b) §8.10 の当該3行を「再現不能・当時の実測メモ」と明記して格下げする。**足さない案は (b)**。

## 2026-09-05 A案実施: 全項目スナップショット取得（本体）
- `data/fetch_nrib_moromi.py`（標準ライブラリのみ）で NRIB の検索フォームに 検索条件=仕込番号・順位1..42 を POST し、`data/nrib_moromi_42_full.json` に42件を機械転記。1件ごとに概要（仕込年度・酵母種類・麹タイプ・備考・糟歩合）、仕込配合（酒母/添/仲/留/四段の総米・蒸米・麹米・汲水）、製成酒分析値（アルコール・日本酒度・酸度・アミノ酸度・グルコース・カプロン酸エチル・酢酸イソアミル・酢酸エチル・イソアミルアルコール）と、表の原文 `raw` を保持。
- 既存 `nrib_moromi_42.json` の8列（no/maxT/maxB/days/alc/nihon/sando/amino）と突合: **42件×7項目で不一致0**。
- 収録年度: 17BY×8・18BY×6・19BY×10・20BY×10・21BY×8。酵母: 901号12・1801号9・1701号7・701号5・601号2・1601号1・混合/赤色酵母ほか。
- **グルコースは42件中25件が空欄**（17BY〜19BY は全件空欄、20BY以降のみ記載）。したがって spec §8.10 の「残糖×日本酒度 r=−0.80」は最大17件でしか計算できない。香気4成分は42件すべて記載あり。
- 台帳: `dev/sake-kb/sources.csv` に `nrib-jitsu-moromi`（T1・データベース・引用専用・FTS未取り込み）を登録。出典表記は「NRIB 実もろみDB 仕込番号N（2026-09-05取得）」。
